## CanonFodder Project Overview

### What It Is
A **reproducible data engineering pipeline** that ingests music listening events (scrobbles) from Last.fm, enriches them with MusicBrainz metadata, stores them in a relational data warehouse, and provides interactive analytics.

---

### Main Building Blocks

**1. Data Sources (HTTP/)**
- `lfAPI.py` - Last.fm API integration: fetches scrobbles, user info, artist MBIDs
- `mbAPI.py` - MusicBrainz API: artist lookups, aliases, country data

**2. Data Warehouse (DB/)**
- `models.py` - 6 SQLAlchemy ORM models:
  - `Scrobble` (fact table), `ArtistInfo`, `ArtistVariantsCanonized`, `UserCountry`, `CountryCode`, `AsciiChar`
- `ops.py` - Bulk inserts with dialect-aware conflict handling (MySQL/PostgreSQL/SQLite)
- Alembic migrations (7 versions) for schema evolution

**3. Core Functions (corefunc/)**
- `pipeline.py` - Main orchestrator with `run_full_pipeline()`, `run_incremental_pipeline()`
- `workflow.py` - Data gathering workflow (`run_data_gathering_workflow`)
- `canonizer.py` - Artist name variant canonization using DBSCAN clustering
- `dataprofiler.py` - Analytics/profiling, visualizations
- `enrich.py` - Artist country enrichment
- `model_server.py` - ML model serving (XGBoost) for predictions
- `llm.py` - LLM-based canonization assistance

**4. Helpers (helpers/)**
- CLI utilities, progress tracking, clustering algorithms, stats, I/O, formatting

**5. Workflow Orchestration (flows/)**
- `cf_ingest.py` - **Prefect flow** with 6 tasks: fetch → enrich → clean → canonize → export → profile
- Retry logic with exponential backoff (up to 8 retries)

**6. Storage**
- `DB/canonfodder.db` (~74 MB SQLite) or MySQL
- `PQ/` - Parquet files (`scrobble.parquet` ~7.4MB, etc.) as analytics layer

---

### Main Pipelines

| Pipeline           | Entry Point                                    | Description                         |
| ------------------ | ---------------------------------------------- | ----------------------------------- |
| **Full Pipeline**  | `corefunc.pipeline.run_full_pipeline()`        | Fetch → Enrich → Clean → Profile    |
| **Incremental**    | `corefunc.pipeline.run_incremental_pipeline()` | Fetch new → Enrich → Clean only     |
| **Weekly Prefect** | `flows/cf_ingest.weekly_ingest_flow()`         | Scheduled pipeline with all 6 tasks |
| **CLI GUI**        | `main.py` → `start_gui()`                      | Interactive steampunk CLI interface |
| **Legacy CLI**     | `main.py --legacy-cli`                         | Direct data gathering               |

### What's in Dev vs Properly Built

**✅ Properly Built (Production-Ready)**
- Full SQLAlchemy 2.0 ORM with proper models and constraints
- Multi-database support (MySQL/PostgreSQL/SQLite)
- Alembic migrations (7 versions)
- Prefect orchestration with retry logic
- API integrations (Last.fm, MusicBrainz)
- CLI interface with steampunk aesthetics
- Test suite (unit/integration/e2e) with 18+ test files
- Parquet export for analytics
- Progress callbacks for all long operations

**🔨 In Development (dev/)**
- `profile.py` - Exploratory data profiling script
- `canon.py` - Canonization experimentation
- `lb_refresh.py` / `lblink.py` - ListenBrainz integration (alternative to Last.fm)
- `test_interactive_mode.py` - Interactive testing

**📋 Documented but Pending**
- Docker packaging ("in the end, we want docker run canonfodder")
- Full BI frontend beyond the CLI (BI_architecture.mmd mentioned but not present)
- ML-powered canonization (model_server.py exists, XGBoost model at `ML/xgb.json`)
