### What It Is

A reproducible data-engineering pipeline that ingests music listening events (scrobbles) from Last.fm or ListenBrainz, enriches them with MusicBrainz metadata, stores them in Parquet files queryable via DuckDB, and provides ML-based artist-name canonisation through fuzzy matching and XGBoost.

---

### Architecture

**1. Source Layer (HTTP/)**
- `lfAPI.py` — Last.fm API: scrobble fetch, MBID enrichment, user country sync
- `lblink.py` — ListenBrainz API: scrobble fetch with `max_ts` pagination
- `mbAPI.py` — MusicBrainz API: artist lookup (country, aliases, disambiguation)
- `client.py` — resilient HTTP GET with retries (tenacity)

**2. Integration Layer (corefunc/)**
- `workflow.py` — data-gathering orchestrator; calls lfAPI or lblink, persists via helpers.io
- `enrich.py` — MusicBrainz artist-country enrichment → artist_info.parquet
- `data_cleaning.py` — deduplicates artist_info by completeness score
- `canon.py` — XGBoost model: builds gold-standard pairs from avc.parquet, trains, evaluates, saves to ML/
- `model_server.py` — FastAPI app: /health, /predict, /predict_batch endpoints

**3. Storage Layer**
- `PQ/` — Parquet files (zstd-compressed), app-layer dedup:
  - scrobble.parquet: artist_name, album_title, track_title, artist_mbid, play_time
  - artist_info.parquet: artist_name, mbid, country, disambiguation_comment, aliases
  - avc.parquet: artist_variants_hash, artist_variants_text, canonical_name, to_link, comment, stamp
  - uc.parquet: country_code, start_date, end_date
  - c.parquet: ISO-2, ISO-3, en_name, hu_name
- `ML/` — xgb.json (trained model), xgb_columns.json (feature list)
- `JSON/` — palettes.json (colour palettes), selected_features.json

**4. Query Layer (helpers/)**
- `query.py` — DuckDB-over-Parquet: top_artists, scrobble_count, unique_artists, artist_country_stats, scrobbles_between, etc.
- `io.py` — Parquet I/O (read/write/append), PyArrow schemas, column aliases, normalise_scrobble_df
- `cli.py` — Click-based interactive prompts: artist-name unification, country-timeline editor
- `cluster.py` — DBSCAN with anchor constraints, fuzzy scoring (6 RapidFuzz metrics), ML-based similarity
- `stats.py` — statistical utilities: Cramér's V, correlation pruning, variance testing, confusion matrix

**5. CLI (main.py)**
Click command group with 9 subcommands: ingest, enrich, canonise, review, train, serve, dashboard, purge, flow.
- `--source` / `-s` on ingest, enrich, flow: accepts lastfm (default), listenbrainz, lb
- `--verbose` / `-v` for debug logging
- Installable as `c9r` entry point via pyproject.toml

**6. Orchestration (flows/)**
- `cf_ingest.py` — Prefect 3.x flow (`c9r_ingest`) with 3 tasks:
  1. fetch_scrobbles — ingests from selected source
  2. enrich_artists — MusicBrainz country/MBID lookup
  3. clean_artists — deduplicates artist_info
- Retries: up to 8 with exponential back-off and jitter
- Source selection: --source flag or C9R_SOURCE env var

**7. Docker**
- Multi-stage Dockerfile (python:3.12-slim + uv)
- `docker build -t c9r . && docker run --env-file .env c9r ingest --user <name>`

### What's Built vs In Progress
